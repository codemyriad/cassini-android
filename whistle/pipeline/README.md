# Desktop preprocessing parity

The first increment adds `WhistleResampler` as a separate, bounded streaming
stage. It implements the published `cassini-fir-48k-16k-v1` contract: fixed
float32 coefficient bits, scalar binary64 multiplication and accumulation in
ascending tap order, one rounding to float32, zero padding only at true track
edges, and ceil(input length / 3) output samples. Mono 16 kHz passes through;
mono 48 kHz uses the FIR. Other rates fail until an explicit decoder policy is
implemented. The stage does not high-pass recognizer audio.

The existing Android/Parakeet decoder and resampler are unchanged. This class is
not yet wired to the app. It has no native runtime, model, network or device
access and is not an Included-readiness or worker-parity claim.

## Checks

Normal `:core:test` uses ten new synthetic reference cases generated by the
**pinned Mac #167 C implementation**, not Android. Cases cover empty input, short
edges, decimation remainders and long blocks; each is fed with up to ten chunk sizes.
The committed JSON records source/coefficient hashes and the input rule. The
coefficient JSON is copied byte-for-byte from the published shared fixture.
The model-free `WhistleResamplerDeviceTest` checks two of those independent
hashes under ART through the existing CiSmoke API matrix.

To independently reproduce candidate synthetic data on the Mac, put this command
under the shared heavy lock, with an external output directory:

```sh
python3 whistle/pipeline/reference-fir.py --mac /path/to/cassini-mac \
  --coefficients core/src/test/resources/whistle/fir-48k-16k.json \
  --output /Volumes/DrMeyers2/fir-reference
```

It verifies the desktop C and coefficient pins before compiling and evaluating
the reference. It does not update the committed test data or existing desktop
goldens. Review differences; do not regenerate expectations from Android.

The explicit public-speech check uses the frozen coordination files without
committing recordings or PCM. Under the shared lock, run:

```sh
./gradlew --configure-on-demand :core:whistleFirConformance \
  -PcassiniWhistleVectorsDir=/path/to/cassini-coordination/ux-draft
```

Missing paths or corrupt inputs fail this task; it never skips them. It requires
an exact clean FIR hash, exact raw PCM hashes for all twelve frozen DC/control
segments from #78, and exact complete-frame high-pass hashes for both DC tracks.
It also compares two decoder chunk sizes byte-for-byte. These are preprocessing
checks at fixed desktop segment boundaries, **not Android VAD segmentation or
word parity**. VAD model/runtime, SpeechGate decisions, worker lifecycle and
checkpoint parity remain separate work. No default, Settings, model storage or
Parakeet behavior changes in this increment.

The completed JVM measurement is recorded in [the evidence](evidence/README.md).

## Reference boundary

Coordination `ux-draft/dc/whistle-reference/v1` preserves an observed desktop
engine discrepancy: GNOME returns 103 words and the #78 Mac candidate returns
104 over the same thirteen raw inputs. Those measurements remain unchanged.
This FIR increment compares PCM bytes, not either transcript. The later worker
comparison must retain both references and report differences; matching one does
not establish word parity with the other.

The scalar C FIR is the reference here. Source inspection also finds that the
current Mac Swift batching limit can emit its first output after only 47 or 48
inputs because negative integer division truncates toward zero. That is earlier
than the required sample at index 48. Android waits for 49 inputs; a dedicated
lookahead test and the independent C outputs cover these small chunk sizes.
This does not change any desktop code or acceptance golden.
