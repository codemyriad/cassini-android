# Native runtime sources

Cassini uses a sherpa-onnx 1.13.7 AAR that it builds itself: upstream release 1.13.7 plus Sortformer speaker diarization for [Nemotron-3-Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization). The source is branch [`feat/nemotron3-diarization-android`](https://github.com/codemyriad/sherpa-onnx/tree/feat/nemotron3-diarization-android) of the Cassini fork: two commits on tag `v1.13.7`, cherry-picked from the contribution for upstream issue k2-fsa/sherpa-onnx#4006. They add the C++ runtime and the Kotlin/JNI configuration; speech recognition code is unchanged. `scripts/streaming-diarization.patch` adds a stateful Sortformer chunk call through C++ and Kotlin/JNI. Its bounded arrival-order speaker cache survives calls; ordinary `process` calls still start independent recordings. `scripts/setup.sh` installs the AAR into the repo-local Maven repository `native/m2` (see [its README](../native/m2/README.md)): it downloads the build attached to the GitHub release `native-sherpa-onnx-1.13.7-nemotron.2` and checks its SHA-256 against the `sherpa-onnx-aar` entry of [the source manifest](../scripts/native-dependencies.json), or builds it from source when the download fails or with `--from-source`. With `--prebuilt-only`, which CI uses, a failed download is an error instead. `scripts/verify-native-runtime.sh` compares the installed AAR with the pin and checks that the patch has not changed since the pin was recorded. The older release `native-sherpa-onnx-1.13.7-nemotron.1` holds a build without the streaming patch; do not use it. The packaged ABIs are arm64-v8a and x86_64. The AAR contains sherpa-onnx JNI and the upstream ONNX Runtime 1.27.1 Android library, including statically linked text-to-speech dependencies that Cassini does not call.

Each release attaches `cassini-native-sources.tar`. Extracting it gives the pinned archives in `sources/` and, at their repository paths, the URL/hash manifest (`scripts/native-dependencies.json`), the incremental JNI patch, the AAR and libopus build scripts, the JNI wrapper with its CMake files, these build notes and the dependency notice index. Run `python3 scripts/package-native-sources.py` to reproduce that bundle. Downloads and archives stay in ignored directories.

## Build

`scripts/build-native-aar.sh` reproduces the AAR. It needs an Android NDK (built with r28c, 28.2.13676358), CMake and JDK 17 or later:

```sh
ANDROID_NDK=$ANDROID_HOME/ndk/28.2.13676358 scripts/build-native-aar.sh
```

It extracts the pinned sherpa source archive from [the source manifest](../scripts/native-dependencies.json) (or uses `SHERPA_ONNX_SRC`), applies `scripts/streaming-diarization.patch`, runs upstream's `build-android-arm64-v8a.sh` and `build-android-x86-64.sh` with `SHERPA_ONNX_ENABLE_C_API=ON` and ONNX Runtime 1.27.1, copies the libraries into `android/SherpaOnnxAar` and runs `./gradlew :sherpa_onnx:assembleRelease` there, as upstream's `.github/workflows/android.yaml` does. The result is installed as `native/m2/org/cassini/native/sherpa-onnx-nemotron/1.13.7-1f23907a/sherpa-onnx-nemotron-1.13.7-1f23907a.aar` with a minimal POM, and the app depends on the coordinate `org.cassini.native:sherpa-onnx-nemotron:1.13.7-1f23907a`. Text-to-speech and speaker diarization stay enabled, as upstream ships them.

ONNX Runtime's source archive includes its build scripts and pinned dependency download metadata. Its Android library build is maintained in [onnxruntime-libs](https://github.com/csukuangfj/onnxruntime-libs/tree/v1.27.1), `.github/workflows/android-shared.yaml`. That workflow provides the Android NDK/API and build flags, and removes the shared-library VERSION/SOVERSION properties from ONNX Runtime's CMake build. Native dependency archives retain their own build scripts and licenses. Downloads of transitive build inputs remain available through those upstream manifests.

These instructions do not claim a byte-for-byte reproduction across different NDK/JDK versions. A build from source that does not match the pinned hash is installed with a warning.

## Resumable processing

The streaming Sortformer patch exports and restores its bounded embedding/FIFO cache and activity probabilities. The app saves this with the ASR overlap window and completed words, selected disk voice clips and sample clocks, using atomic metadata commits after completed chunks. Labels and merges commit independently. Decoding seeks with one second of preroll and preserves the absolute resampling phase.

Same-pass streaming encoding uses libopus 1.5.2. `scripts/fetch-opus-source.sh` (run by `scripts/setup.sh`) downloads the hash-pinned source into `.tools/opus/source`, and the Gradle build compiles `libcassini_opus.so` from it for arm64-v8a and x86_64 (`externalNativeBuild`, CMake 3.22.1, NDK 28.2.13676358, `engine/src/main/cpp/CMakeLists.txt` in the `:engine` module). Every variant, debug included, compiles with the CMake Release flags (`-O3 -DNDEBUG`), so the encoder behaves the same in every build; the result is identical in code and data to the library the former `scripts/build-opus-jni.sh` produced. libopus encoder state is not saved, because it holds absolute pointers into the library. A checkpoint keeps the last two encoded frames, the incomplete PCM frame, the pending Ogg packet, the serial, sequence and granule clock; restore truncates any uncommitted file tail, and the resumed encoder re-encodes the two saved frames and drops their packets, so its lookahead holds the same audio and the stream continues on the same clock. The encoder's longer-term state is not restored, so packets after a resume point need not match an uninterrupted encode byte for byte. On the x86_64 API 34 emulator they differ from the first packet after the checkpoint, with 0.1.0 and with the current build alike, so `DeviceSmokeTest#opusCheckpointContinuesIdenticalPacketsAfterClosingTheEncoder` is ignored. `DeviceSmokeTest#opusCheckpointContinuesTheSameStreamAfterClosingTheEncoder` checks what a resume does guarantee: valid framing, identical packets up to the checkpoint, the same packet count, granule clock and duration, and decoded audio within 1 % of the signal power of the uninterrupted encode (measured: 0.2 %). The source URL/hash and BSD license are in the dependency manifest and APK notices.
