# Android Files-app access (`CassiniDocumentsProvider`, D97)

`CassiniDocumentsProvider` (`${applicationId}.documents`) exposes Cassini's note library **read-only** to the Android system file picker and Files app (`android.content.action.DOCUMENTS_PROVIDER`, decision D97) without adding any IPC, broadcast, or `adb` command surface to release builds.

## Why read-only

- **Outbound sharing and browsing**: external apps and the system Files UI can browse and read live, finished Cassini notes through Android's standard `ACTION_OPEN_DOCUMENT` / `ACTION_GET_CONTENT` picker (`audio/*`, `application/ogg`) without manual export staging.
- **Inbound importing stays on Cassini's reviewed import paths**: importing audio or portable `.opus` documents into Cassini continues through Share / Open with (`MainActivity` + `ImportGrantService`), the Library multi-file picker (`OpenMultipleDocuments`), and ZIP archive import (`LibraryTransfer`, D96), where Cassini pulls from the source URI under its own storage, deduplication, and error-reporting lifecycle rather than staging untrusted inbound streams over a `DocumentsProvider` write descriptor.
- **No write or mutation flags**: `queryRoots` advertises `Root.FLAG_LOCAL_ONLY | Root.FLAG_SUPPORTS_IS_CHILD` (never `Root.FLAG_SUPPORTS_CREATE`); `"root"` and `"note:<uuid>"` rows advertise `Document.COLUMN_FLAGS = 0` (never `FLAG_DIR_SUPPORTS_CREATE` or `FLAG_SUPPORTS_WRITE`); `createDocument`, `deleteDocument`, `removeDocument`, `renameDocument`, `moveDocument`, and `copyDocument` throw `UnsupportedOperationException`; and `openDocument` accepts `"r"` (`ParcelFileDescriptor.MODE_READ_ONLY`) only, rejecting `"w"`, `"wt"`, `"wa"`, `"rw"`, and `"rwt"` immediately with `SecurityException` before touching Room or note files.

## Access boundary and threat model

- **Caller restriction (`MANAGE_DOCUMENTS`)**: the provider is declared with `android:exported="true"`, `android:grantUriPermissions="true"`, and `android:permission="android.permission.MANAGE_DOCUMENTS"`. On Android, `MANAGE_DOCUMENTS` is a `signature` platform permission held only by the system document picker (`DocumentsUI` / Files). Third-party apps cannot query or open `CassiniDocumentsProvider` directly; an external app receives a scoped, temporary read-only URI grant only when the user explicitly selects a document in the system UI.
- **No access beyond manual export**: only live (`trashed_at IS NULL`), finished notes backed by regular non-symlink files inside `notes/<noteId>/` are exposed:
  - Notes with a sealed Cassini document (`audio_kind == DOCUMENT` and `document.opus` present) expose `document.opus` (`audio/ogg`), containing audio, transcripts, speaker names, title, recording timestamps, and provenance — never voiceprints (`voices/` is never read or referenced). If `title_dirty` is set on an `OK` document with no job row, `DocumentRepository.retitle(noteId)` flushes the latest title into `document.opus` before `COLUMN_SIZE` or a read descriptor is returned; unedited imported documents (`title_dirty == false`) and non-`OK` quarantined documents are streamed byte-for-byte without rewriting. Unlike `DocumentRepository.exportCopy` (which stages a temporary annotated copy in `cacheDir/exports/` when a legacy pre-D95 document lacks `recorded_at_utc`), `openDocument` returns a direct read-only descriptor over the canonical on-disk `document.opus` with zero temporary copies.
  - Plain-audio notes (`audio_kind == PLAIN`) expose their original audio file (`capture.opus`, `capture.m4a`, or `source.<ext>`) with its container MIME type.
  - Active recordings (`audio_kind == LIVE_CAPTURE`), unplayable entries (`audio_kind == UNPLAYABLE`), notes with a running transcription job (`JobState.RUNNING`), notes with an un-adopted seal (`work/sealed` or `work/sealed.opus`), and trashed notes (`trashed_at IS NOT NULL`) are omitted from `queryChildDocuments`, return `false` from `isChildDocument`, and throw `FileNotFoundException` on `queryDocument` / `openDocument`.
- **Self-URI loop prevention**: `DeepLinks.external` includes `"documents"` in `OWN_PROVIDER_SUFFIXES`, so `MainActivity` never re-imports a `CassiniDocumentsProvider` URI from the same build variant as an external deep link while still allowing side-by-side debug (`io.codemyriad.cassini.talk.debug`) and release (`io.codemyriad.cassini.talk`) variants to share documents with each other.
- **Unforgeable UUID document IDs**: only `"root"` and `"note:<uuid>"` exist, where `<uuid>` must satisfy `NoteIds.isValid` (canonical lowercase UUID) and `audioFile` must be a single non-`.`/`..`/`.tmp` filename resolving as a direct regular non-symlink child of `AppPaths.note(id)`.

## Startup readiness, threading, memory, and scaling

- **Cold-start readiness gate (`AppGraph.ready`)**: `isChildDocument`, `queryChildDocuments`, `queryDocument` (for `"note:<uuid>"`), and `openDocument` wait for `AppGraph.ready` before reading the catalogue (honoring `CancellationSignal` in `openDocument` via `OperationCanceledException`), so cold-start access over a recreated database waits for `STEP_REBUILD`, `STEP_PURGE`, `STEP_SWEEP`, and `STEP_RETITLE` to finish rather than returning an empty or pre-rebuild view.
- **Off-main, zero-buffer streaming**: `queryRoots` and `queryDocument("root")` perform no disk or database I/O; `isChildDocument`, `queryChildDocuments`, `queryDocument("note:<uuid>")`, and `openDocument` reject main-thread calls (`Threads.assertOffMain`), run Room/metadata checks on `CassiniDispatchers.io`, never read the `words` table or decode transcripts into heap, and open files under `NoteLocks.withNoteLock` with `ParcelFileDescriptor.MODE_READ_ONLY`.
- **Deterministic `O(N)` collision naming**: display names use `ExportNames.file(title, ext)` with case-insensitive collision numbering (`Title (2).opus`, `Title (3).opus`, ...) assigned in chronological (`created_at ASC, id ASC`) order via per-stem suffix counters in `O(N)` time, keeping `queryDocument` and `queryChildDocuments` consistent while listing notes newest-first (`created_at DESC, id ASC`).
- **Live observer updates**: Room `InvalidationTracker` observation on `notes` and `jobs` calls `ContentResolver.notifyChange` on the child-documents URI so an open Files window updates automatically when notes are imported, sealed/adopted, renamed, restored, or moved to Trash.
