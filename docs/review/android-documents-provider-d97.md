# Android Files-app access (`CassiniDocumentsProvider`, D97)

`CassiniDocumentsProvider` (`${applicationId}.documents`) exposes Cassini's note library to the Android system file picker and Files app (`android.content.action.DOCUMENTS_PROVIDER`, decision D97) without adding any IPC, broadcast, or `adb` command surface to release builds.

## Access boundary and threat model

- **Caller restriction (`MANAGE_DOCUMENTS`)**: the provider is declared with `android:exported="true"`, `android:grantUriPermissions="true"`, and `android:permission="android.permission.MANAGE_DOCUMENTS"`. On Android, `MANAGE_DOCUMENTS` is a `signature` platform permission held only by the system document picker (`DocumentsUI` / Files). Third-party apps cannot query or open `CassiniDocumentsProvider` directly; an external app receives a scoped, temporary URI grant only when the user explicitly picks or saves a document through the system UI.
- **No access beyond manual export**: only live (`trashed_at IS NULL`), finished notes are exposed, read-only (`ParcelFileDescriptor.MODE_READ_ONLY`, `Document.COLUMN_FLAGS = 0`):
  - Notes with a sealed Cassini document (`audio_kind == DOCUMENT` and `document.opus` present) expose `document.opus` (`audio/ogg`), containing audio, transcripts, speaker names, title, recording timestamps, and provenance — never voiceprints (`voices/` is never read or referenced). If `title_dirty` is set and no job row exists, `DocumentRepository.retitle(noteId)` flushes the latest title into `document.opus` before `COLUMN_SIZE` or a read descriptor is returned, matching `DocumentRepository.exportCopy`.
  - Plain-audio notes (`audio_kind == PLAIN`) expose their original audio file (`capture.opus`, `capture.m4a`, or `source.<ext>`) with its container MIME type.
  - Notes currently being recorded (`audio_kind == NONE`), notes with a running transcription job (`JobState.RUNNING`), and notes with a pending seal (`work/sealed` or `work/sealed.opus` awaiting `SealedAdopter`) are omitted from `queryChildDocuments` and refused with `FileNotFoundException` on `queryDocument` / `openDocument` until adopted.
- **Read-only existing notes, isolated persistent creation grants**:
  - `openDocument` on `note:<uuid>` accepts `"r"` only; `"w"`, `"rw"`, `"wa"`, and `"rwt"` throw `SecurityException`.
  - `deleteDocument`, `removeDocument`, `renameDocument`, `moveDocument`, and `copyDocument` throw `UnsupportedOperationException` (and no `FLAG_SUPPORTS_*` mutation flags are advertised on note rows).
  - The root advertises `Root.FLAG_SUPPORTS_CREATE | Root.FLAG_LOCAL_ONLY | Root.FLAG_SUPPORTS_IS_CHILD` and `Document.FLAG_DIR_SUPPORTS_CREATE`. `createDocument` allocates a stable `pending:<uuid>` document ID persisted under `filesDir/provider-grants/<uuid>/meta.json` (`AWAITING_WRITE`).
  - **Bounded streaming via kernel pipe (`ParcelFileDescriptor.createPipe()`)**: opening a created document for write accepts pure write-only non-append modes (`"w"` and `"wt"`) and rejects read-write or append modes (`"rw"`, `"rwt"`, `"wa"`) with `UnsupportedOperationException` **before** consuming the write-once `pending:<uuid>` grant. A `"w"`/`"wt"` open returns the write end of an OS pipe while a background pump streams incoming bytes into `payload.tmp`, enforcing `ImportLimits.maxBytes` (4 GiB) and `ImportLimits.minFreeBytes` **during streaming before writer close**. Exceeding either limit or cancelling closes the read end immediately (delivering `EPIPE` / `IOException` to the writer before `close()`) and deletes the staging directory even if the writer keeps its descriptor open. Because completion follows kernel pipe EOF rather than `ParcelFileDescriptor.OnCloseListener`, native writers that call `detachFd()` continue writing safely until they release the detached descriptor.
  - **Creation-grant byte isolation, note-lifecycle binding, and startup recovery**: on clean pipe EOF, the payload is atomically moved to `<uuid>/<displayName>` (`state = IMPORTING`), imported through `ImportRepository` (container validation + internal SHA-256 `source_sha256` deduplication), marked read-only, and persisted as `state = ACCEPTED` alongside the associated `noteId`. Accepted creation grants retain **only** the caller's submitted bytes and metadata on disk and always report their original `pending:<uuid>` `COLUMN_DOCUMENT_ID` across provider recreation, restarts, and cache eviction — never resolving to or exposing an existing note's mutable transcript, speaker names, or title. Each accepted grant follows its note's lifecycle: hidden while the note is in Trash (`trashed_at IS NOT NULL`), restored if the note is restored from Trash, and deleted from `filesDir/provider-grants/` via `NoteFilesCleaner` when the note is permanently purged (`deleteNow`, `emptyTrash`, `purgeExpired`). On `AppGraph` startup (`STEP_SWEEP`), `PendingImports.reconcileStartup()` runs serialized and idempotently to import any interrupted `IMPORTING` grant without waiting for the sender to reopen its URI, sweep crashed `WRITING` or expired placeholder directories, and remove grants whose notes were purged.
- **Self-URI loop prevention**: `DeepLinks.external` rejects Cassini's own provider authorities, so `MainActivity` never re-imports a `CassiniDocumentsProvider` URI as an external deep link.
- **Strict UUID path resolution**: both `note:<uuid>` and `pending:<uuid>` document IDs require canonical lowercase UUIDs (`NoteIds.isValid`) and resolve exclusively inside `AppPaths.note(id)` or `filesDir/provider-grants/<uuid>/`.

## Threading, memory, and scaling

- `queryRoots` performs no disk or database I/O and returns immediately.
- `queryChildDocuments`, `queryDocument`, `createDocument`, and `openDocument` reject main-thread calls (`Threads.assertOffMain`), dispatch Room/metadata lookups on `CassiniDispatchers.io`, never touch the `words` table or decode transcripts into memory, and return read-only `ParcelFileDescriptor` handles without buffering whole files in heap.
- Display names use `ExportNames.file(title, ext)` with case-insensitive collision numbering (`Title (2).opus`, `Title (3).opus`, ...) computed in chronological (`created_at ASC, id ASC`) order via per-stem suffix counters in `O(N)` time, keeping `queryDocument` and `queryChildDocuments` consistent.
- Room `InvalidationTracker` observation on `notes` and `jobs` calls `ContentResolver.notifyChange` on the child-documents URI so an open Files window updates automatically when notes are imported, sealed/adopted, renamed, or moved to Trash.
