# D-990: Phase 1 Android QA revision

Reviewed the Phase 1 implementation against the shared BRAND, HARMONY, STATUS-BADGES,
PARITY and string contracts, and the local WP2–WP5 specifications. Shared inputs remain
at the checksum-pinned cassini-ux commit `5e0c34e0f1bb390298dabdf4eedc494e933fd329`.
The review uses synthetic fixtures only.

## Findings and fixes

1. A narrow phone with larger text cuts the full sub-minute transcription badge because
   StatusChip forces every label onto one line. Allow the label to wrap and the pill to
   grow above its 22dp minimum. Keep the exact catalog copy, glyph, tone and default-size
   metrics. The same rule protects longer translated problem labels.
2. Checked Library Resume and Try again hit targets. Although their visible bounds are
   text-sized, Compose expands their hit areas to 48dp. The existing component test
   verifies a tap outside the visible label reaches Resume. Retain this behavior and the
   compact row layout rather than enlarging the visual bounds.

`LibraryAccessibilityScreenshotTest` captures both themes at 320dp width and 1.5x text
and checks status/recovery text layout. `Phase1BadgeTest` checks full sub-minute, paused
and unreadable labels in constrained space at 1.5x text in all six app languages.
`ComponentSemanticsTest` retains its expanded-hit-area regression for inline recovery.

## Retained contract differences

The search backend returns one result per meeting, so the existing heading uses the shared
meeting-count plural. It does not claim a count of matching places; see [WP2](phase1-wp2.md).
Phone clocks retain the existing Android clock format; desktop formatting does not replace
the phone board specification in this QA revision. Existing phone states and export formats
remain as listed in PARITY. Open decisions about phone Imported eligibility and resting
search filters are not resolved here. Legacy Name a speaker copy is already present in the
shared phone catalog; no new app-local English or translations are introduced.

## Validation boundary

This macOS host has no working JDK or Android SDK. Python contract, resource, pin and link
checks run locally. GitHub Actions supplies JDK 17, the pinned Android tools, all module
tests, Linux screenshot verification, static analysis, lint, and API 26/35 emulator smoke
checks. The revision does not claim manual physical-device recording or audio-model QA.
No persistence, recording lifecycle, format, queue, search indexing or transcript algorithm
changes are made.
