# WP2: Android Library and search

The Nov 12 decisions L-26, L-30..35 and L-50..53 are the authority. This package replaces the row portion of #200 and the action controls of #202, based on merged WP1. No schemas, authoritative document writers or search engine behaviour change.

The native Material 3 SearchBar/InputField stays pinned above the list, without a scroll-edge line or tonal overlay. Its bounds and icon slots stay fixed: the approved Saturn image at rest, Back/Clear while searching, Trash/Settings at rest. Icons crossfade. Empty focused search also handles system Back; Clear retains search focus. Existing delayed StateFlow acknowledgement keeps newer typed text intact.

All meetings is a semantic heading without visible title text. Shared `library.allMeetings` and `library.backToAllMeetings` replace the old phone Library labels, including recording navigation. The narrow native field uses shared `common.search` as its short visible hint and `search.field.a11y` as its full accessible description. The board’s phone-specific “Search meetings” placeholder has no dedicated shared catalog entry; this is listed as a catalog gap in the PR. The desktop-only full placeholder is too long in French for the phone bar. No translated app copy or overflow exception is added.

Rows keep two-line titles, durations, dates/times and every phone state/recovery action. Finished rows have no Transcribed chip: one or more speakers use a neutral people/count pill; an empty transcript uses No speech. Resume/Try again are ink semibold with no middle dots. TalkBack still gets the established localized state and recovery actions. Ordinary list quotes are hidden, but matching search snippets and highlights remain.

The backend currently supplies one result per meeting, so the summary reports the actual meeting count via `format.searchCount.meetings`. It does not invent a count of matching places or add a hit-level search backend. Existing speaker/date/Recorded by me filters are unchanged (L-34/35 remain open). A running row receives quantized ETA from its own note only; second-level processing ticks do not invalidate the entire listing cache.

Import/Record adopt the reviewed #202 56dp Record control, pressure/focus feedback and measured list inset. Existing recording return feedback and problem/import banners remain. Model download/verification cards also remain, including standalone installs and their Open settings action; only duplicate transcription progress is removed. Empty search follows actual field focus, and toolbar/system Back clear local text through the same handler even before a ViewModel acknowledgement. BulkTransferControls and its activity launcher, choices, progress/results live above the lazy list in LibraryRoute; only the export trigger can be disposed by scrolling.

The full approved SVG at cassini-ux 5e0c34e is vendored unchanged. Its gradients/filters are rasterized by WebKit, not approximated with a vector importer. `scripts/render-nav-mark.swift` accepts SVG path, PNG path and output width. Five density exports are recorded in `scripts/nav-mark.json`; `check-nav-mark.py` checks the source hash, every output hash/dimension and complete density inventory. CI mutations reject SVG/PNG drift and omitted densities. To regenerate on macOS, run `~/bin/heavy-run swift scripts/render-nav-mark.swift <svg> <png> <width>` using the receipt widths, inspect all outputs, and update the receipt.

Validation includes six-locale spoken/visual row coverage, fixed search bounds under a long actual scroll, empty-search Back/Clear/focus, late query state, count/no-speech pills and snippet visibility, recovery actions, large text, action-button pressed/focus states, runtime-image drift mutations and existing scrolled bulk-transfer device coverage. Linux alone records/verifies Roborazzi goldens; both light and dark comparisons are published before ready.
