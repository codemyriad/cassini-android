# Phase 1 WP3: Android meeting view

Based on the approved Phase 1 Android Meeting, Find, Scrolled and Player boards and L43/L55/L56. Android keeps the title in its native M3 top bar, as specified in the brief. Back says Back to all meetings; Search, Share Cassini document and More actions use existing navigation/export actions. The compact scrolled bar keeps Android’s hairline. No summary/tab/bookmark features are added.

In Reading mode, recording date/duration, inline speaker names and existing trust/version controls and their banners are one scrolling transcript header. Queued/failed document modes retain their existing bar metadata without duplicating it below. Stored names and first-speech palette slots come from the existing mapped transcript, cached when it is built (including overlap-only speakers). Naming delegates to the existing SpeakerTap validation. Unnamed names have a soft underline; each speaker remains a 48dp target with its existing spoken naming action and automatic provenance. Long names leave room for the automatic badge. When inline speakers are present in Reading mode, their redundant count is omitted while the trust/version actions remain. The resting native bar and header share one continuous ground surface, followed by a single 1dp divider into the transcript; only the scrolled bar adds its own hairline. No writer/schema/colour allocation changes.

The adaptive native Find bar uses a paddingless text field and retains the existing query acknowledgement, match counter, next/previous actions and IME policy. Find omits the metadata header, as on the approved Find board; closing it at the first turn restores the normal scrolling header. Opening Find partway through metadata resets its old pixel offset; closing a deep result keeps its location. At large text the counter and 48dp navigation targets move to a second row to preserve at least 120dp of editable query space. The transcript owns the single boundary divider. Header item offsets apply to both playback-follow and match jumps, with stable turn keys. Tests use a short viewport and tall turns so an off-by-one target cannot accidentally be visible.

The player retains its Material 3 Slider, transport semantics and callbacks in a Material 3 Surface. Speed uses the board’s leading outline pill. Both compact and upright layouts measure its actual localized text; larger text gets a separate leading row when needed instead of covering transport targets.
